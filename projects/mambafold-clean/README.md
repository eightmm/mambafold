# mambafold-clean

MambaFold trained on a corpus that reproduces SimpleFold's data admission rule,
so the benchmark claims and the architecture claim rest on one unambiguous
contract.

It is a separate project root rather than a branch of the previous ESMC-6B
track because the two corpora make contradictory statements about the same
benchmarks: under the old contract CASP14 carries six exact training matches and
is development-only, under this one it carries none and is reportable. A shared
namespace would let a number be cited against the wrong contract. Nothing from
the previous track's configs, results, or benchmark tables carries over.

- Data contract and evidence: [`docs/data_contract.md`](docs/data_contract.md)
- Build the corpus: [`pipeline/README.md`](pipeline/README.md)
- Reporting rules: [`benchmarks/BENCHMARK_POLICY.md`](benchmarks/BENCHMARK_POLICY.md)

## Getting the data

```bash
./pipeline/run_all.sh              # every stage, resumable
sbatch scripts/slurm_build_data.sh # the same, on a compute node
```

The ordered pipeline goes from an empty `data/` to a frozen, leakage-gated corpus.
External inputs are declared in [`config/paths.env`](config/paths.env) and
nowhere else.

## Training

Run A uses rigid-aligned flow matching plus chunked exact all-atom lDDT:

```bash
PYTHONPATH=src python scripts/train.py --config configs/run_a_mamba.yaml
# DDP example
PYTHONPATH=src torchrun --nproc_per_node=8 scripts/train.py \
  --config configs/run_a_mamba.yaml
```

## What this project claims

RCSB coordinates are admitted only when the entry was released on or before
2020-05-01 and the record passes the reference size rule — the same admission
SimpleFold applies in `configs/data/pdb.yaml`. The distillation stream is
AlphaFold DB SwissProt **v4**, whose generator, AlphaFold 2, has a 2018-04-30
training cutoff.

The date rule does its job on the experimental half: exact sequence overlap
with CASP14, CASP15, and CASP16 is zero against the admitted RCSB corpus, where
the previous track's corpus matched six, two, and two targets. The 2020-05-01
release cutoff is the convention ESMFold and other post-CASP14 folding models
report against; AlphaFold 2's own cutoff is the earlier 2018-04-30.

The distillation half is not date-filtered — SimpleFold does not filter it
either — and AFDB SwissProt covers UniProt, so natural proteins that later
became CASP targets are in it verbatim. Against the full RCSB ∪ AFDB v4 corpus:

Two gates run, and the second is not a formality. Exact identity is checked
against both sources; then MMseqs2 screens at 30% identity over 80% of the
query. Homology exclusions subsume the exact ones:

| Benchmark | Targets | Exact | Homology | Scoreable |
| --- | ---: | ---: | ---: | ---: |
| CASP14 whole-chain | 70 | 0 | 8 | **62** |
| CASP15 strict single-chain | 22 | 1 | 3 | **19** |
| CASP16 strict single-chain | 21 | 2 | 3 | **18** |

The exact gate alone would have called CASP14 completely clean. It is not:
`T1045s1` is a 154-residue *prefix* of a 157-residue training sequence, so every
residue of the target appears verbatim in training while whole-string equality
says no match. `T1100` sits at 92.5% identity, `T1133` at 92.8%. And the date
cutoff removes exact matches but not homologs — `T1157s2` and `T1280` are
excluded on 40% and 39% identity to RCSB entries admitted long before the
cutoff.

Report coverage as 62/70, 19/22, and 18/21.

This is a coordinate-training claim. It says nothing about what ESMC-6B saw
during sequence pretraining, and it does not replace the MMseqs2 homology
screen that must precede any generalization claim.

## Provenance, not a copy

`src/` and the pipeline are real code. The data is not copied: both roots sit on
one filesystem, so structure records are symlinks into the frozen Boltz
snapshot and embeddings are hard links into the previously computed ESMC-6B
cache. Linking costs directory entries and no data blocks.

Admitted records and post-cutoff records live in separate directories, so a
training run pointed at `data/rcsb_train/` cannot reach a post-cutoff structure
through its data directory. The post-cutoff pool is the confirmatory selection
set — the only set that may be used to choose a checkpoint or sampler.

## Layout

| Path | Contents |
| --- | --- |
| `pipeline/` | the nine numbered data stages, their driver, and shared helpers |
| `config/paths.env` | every external input, declared in one place |
| `src/mambafold/` | model, losses, sampler, data pipeline |
| `benchmarks/` | the admission policy, the exact-overlap gate, benchmark FASTAs |
| `scripts/` | training entry point and Slurm submission |
| `data/` | generated by the pipeline; never tracked |
| `docs/` | the data contract and, later, results |

`configs/` contains the checked-in run contracts. `outputs/`, `logs/`, and
`docs/results/` are generated locally and never tracked.

## Deliberately absent

- **AFESM.** SimpleFold-360M pretrains with it; this corpus does not, which
  makes this corpus a strict subset of SimpleFold's and any parity result a
  conservative one.
- **Geometry, chirality, dRMSD, and clash losses.** The objective is flow
  matching plus all-atom lDDT, matching the reference recipe. Those terms were
  tuned against CASP14 in the previous track, so dropping them also removes
  that development exposure.
- **Trunk attention and the pair stack.** Both were deleted from `src/`, not
  defaulted off, so neither is reachable by config. A trunk that could be given
  attention by flipping a flag cannot carry the claim that a pure SSM trunk
  suffices, and a disabled O(L²) triangle path still has to be sized at every
  crop decision. The final Run A folding model is 370.48M parameters; its only
  outputs are all-atom velocity and the trunk latent.
- **The confidence head.** Confidence is a later training phase on a frozen
  folding model, so neither its head nor its loss is part of this baseline.
- **AFDB v6 coordinates.** Generated 2025-08-01 by a model whose training
  cutoff is not established here.
- **Guidance and the previous track's sampler tuning.** Sampling has one
  batch-first ODE/SDE implementation; batch size one uses that same path.

## Known deviations from SimpleFold

| Item | SimpleFold | Here |
| --- | --- | --- |
| PLM | ESM2-3B | ESMC-6B, 2560-d |
| Trunk | transformer with full self-attention | pure Mamba, no attention |
| Chains | assemblies up to 300 chains | single-chain monomers only |
| Distillation | PDB + SwissProt + AFESM | PDB + SwissProt v4 |
| Crop | 256 → 512 | one fixed 1024 crop with 64-residue shape binning |

There is one arm. A parameter-matched transformer control trunk was planned and
cancelled — see `benchmarks/BENCHMARK_POLICY.md` — so the comparison is against
the released SimpleFold checkpoint, which is a public baseline and not a
controlled ablation. Results therefore describe how this model scores, not what
the trunk mixer accounts for.
